# Documentation management

Keep existing documentation consistent with delivered implementation and verified behavior. Use the project's established docs directory and split/combined conventions; avoid duplicate or unrelated documentation.

Documentation commands have concrete outputs: initialize needed overview/summary/architecture/standards, summarize from the existing codebase summary into a report without rewriting it unless requested, and update affected README and technical references. Keep application code unchanged during documentation-only work. Change project instructions (`AGENTS.md` or `CLAUDE.md`) only when requested.

During plan-driven delivery, update the affected phase and overview status after acceptance checks, and reconcile existing roadmap or changelog entries when the change warrants it. Never fabricate percentages, completed milestones or test results.

Verify commands, resource paths, local links and version claims. Keep usage guidance in English and Vietnamese. Retain document schemas, templates, assets and source terms. Disclose version-specific examples or checks that have not been revalidated.
